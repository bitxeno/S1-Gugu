# S1 Goose 本地数据模型文档

> 技术选型:SQLiteData 1.12+(Point-Free,基于 GRDB + StructuredQueries)。单库 `s1goose.sqlite`,全部表 STRICT。
> 对照:S1-Next 两个 Room 库(s1.db v10 + cache.db v2)的 iOS 归一。

## 1. 表结构(SQLiteData @Table)

### 1.1 blackList(用户黑名单)
对齐 S1-Next `BlackList` 实体。过滤发生在模型组装层(架构文档 §1),两个维度 × 两种强度:

| 列 | 类型 | 说明 |
|---|---|---|
| id | Int PK 自增 | |
| uid | Int 索引 | 用户 uid |
| name | String? 索引 | 用户名(uid/name 可能只知其一,查询时合并) |
| postLevel | Int | 回复强度:0 normal / 1 hide(占位) / 2 delete |
| forumLevel | Int | 主题强度:0 normal / 3 hide / 4 delete |
| remark | String? | 备注(占位卡文案) |
| timestamp | Date | 添加时间 |

```swift
@Table struct BlackListEntry: Identifiable {
  let id: Int
  var uid: Int
  var name: String?
  var postLevel: Int = 0
  var forumLevel: Int = 0
  var remark: String?
  var timestamp: Date
}
```

### 1.2 blackWord(屏蔽词)
| 列 | 类型 | 说明 |
|---|---|---|

| level | Int | 1 hide / 2 delete(正文/标题 like 匹配) |
| timestamp | Date | |

### 1.3 history(浏览历史)
对齐 `History` 表,上限 300 条(插入后裁剪最旧)。
| 列 | 类型 | 说明 |
|---|---|---|
| threadId | Int 主键(自定义 PK) | |

### 1.4 readProgress(阅读进度)
对齐 `ReadProgress`,但**锚点改为楼层 pid**(Android 用 RecyclerView offset,与 UI 耦合;iOS 用 pid 语义稳定):
| 列 | 类型 | 说明 |

## 2. Keychain 条目

service = `com.bitxeno.s1goose.account`,kSecClassGenericPassword,单条 JSON:

```json
{ "uid": 123456, "name": "xxx", "password": "…", "questionId": 0, "answer": "" }
```
- 写入时机:登录成功。登出默认保留凭据(下次自动填充),「清除账号数据」才删。
- 会话本身:HTTPCookieStorage(系统持久化,不进 Keychain)。

## 3. UserDefaults 设置项(对齐 S1-Next pref keys 的子集)

| Key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `wifiOnlyImages` | Bool | false | 仅 Wi-Fi 加载帖子大图(头像始终加载) |
| `autoSaveProgress` | Bool | true | 离开帖子自动存进度 |
| `autoRestoreProgress` | Bool | true | 进帖自动恢复进度 |
| `hasNewPm / hasNewNotice` | Bool | false | Tab 角标(M2) |
| 其余(字号缩放/签名尾巴/自定义 host 等) | — | — | M3 增补 |

封装:`AppSettings` 枚举(`@MainActor final class` + UserDefaults 读写),不用 SQLite 存设置。

## 4. 访问模式与迁移策略

- 入口:`appDatabase()` 依 SQLiteData 指南——`defaultDatabase(configuration:)` + `DatabaseMigrator`;DEBUG `eraseDatabaseOnSchemaChange = true`。
- 服务层读取示例(黑名单快照):
```swift
let rows = try await database.read { db in
  try BlackListEntry.order { $0.id }.fetchAll(db)
}
```
- 写入统一 `database.write`,配合 `withErrorReporting` 捕获(不向 UI 抛)。
- 迁移:一个 migration 一个版本(`"v1-create-tables"`);后续加表/列注册新 migration;禁止删历史 migration。
- 测试:`SQLiteDataTestSupport` + in-memory DB(单测 ResponseCleaner / BlockSplitter / 过滤逻辑时使用)。

## 5. 内存加速结构

| 服务 | 结构 | 失效时机 |
|---|---|---|
| BlacklistService | `blacklistSnapshot: Snapshot`(uid set + name set + 词列表) | 表写入后重建;启动时加载 |
| HistoryService | 无缓存(低频写,读仅历史页) | — |
| SessionStore | formhash / uid / name(内存) | 每次响应校验更新 |

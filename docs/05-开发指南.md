# S1 Goose 开发指南

> 面向本仓库的开发与构建手册。文档集:01 产品设计 / 02 技术架构 / 03 API 协议 / 04 数据模型 / 本篇。

## 1. 环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| Xcode | 27.1+(Swift 6.4 工具链) | SQLiteData 需要 swift-tools 6.4 |
| xcodegen | 已安装(/opt/homebrew/bin/xcodegen) | 生成 .xcodeproj,勿手改工程文件 |
| 模拟器 | iPhone 17/18 系列 | `xcrun simctl list devices available` |

## 2. 依赖(SPM)

| 包 | 用途 | 版本策略 |
|---|---|---|
| pointfreeco/sqlite-data | 本地库(@Table/@Fetch) | from 1.12.0(需 tools 6.4) |
| SnapKit/SnapKit | Auto Layout DSL | from 5.7.0 |
| scinfu/SwiftSoup | HTML 解析(渲染管线) | from 2.8.0 |
| onevcat/Kingfisher | 图片加载与磁盘缓存 | from 8.0.0 |

依赖只进 App target;不引入 Alamofire/URLImage 等(UIKit + URLSession 足够)。

## 3. 构建与运行

```bash
# 生成工程(修改 project.yml 或增删文件后重新执行)
xcodegen generate

# 编译验证
xcodebuild -project S1Goose.xcodeproj -scheme S1Goose \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' build

# 运行
xcrun simctl boot "iPhone 18 Pro" && open -a Simulator
xcodebuild -project S1Goose.xcodeproj -scheme S1Goose \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' build
xcrun simctl install booted <path/to/S1Goose.app> && xcrun simctl launch booted com.bitxeno.s1goose
```

- Swift 6 语言模式;并发严格(UI 全 @MainActor)。
- 新增源文件只需放入 `S1Goose/` 目录树后重新 `xcodegen generate`(project.yml 按目录聚合)。

## 4. 代码约定

- 命名:类型 UpperCamel;VC 后缀 `ViewController`;Service/Repository 后缀全称。
- 布局:SnapKit;frame-only 场景(自尺寸 cell 内部)允许手写。
- 颜色:只用语义色与 `Theme.accent`;禁止硬编码 hex(Asset Catalog 除外)。
- 字体:`UIFont.preferredFont(for:)` + `adjustsFontForContentSizeCategory = true`。
- 注释:仅在协议/管线边界处写「为什么」,不复述「做了什么」。
- 错误:`APIError` → `UserFacingError`(中文文案)在 Service 层转换;VC 只展示。

## 5. 里程碑任务拆解

### M1 checklist(按实施顺序)
1. **脚手架**:project.yml(xcodegen)+ AppDelegate/SceneDelegate + RootTabBarController(4 Tab 骨架+占位页)→ 编译通过
2. **网络层**:APIError / ResponseCleaner(单测覆盖)/ S1APIClient / DiscuzMobileAPI(forumindex·forumdisplay·viewthread·login·toplist·favthread)→ 可请求真实接口
3. **数据层**:appDatabase() + 四表迁移 + 各 Service(Blacklist/BlackWord/History/ReadProgress)
4. **论坛 Tab**:ForumGroupsVC → ThreadListVC(无限滚动、黑名单主题过滤、已读样式)
5. **渲染管线**:PostPreprocessor → BlockSplitter → HtmlAttributedBuilder(后台执行,单测覆盖典型 Discuz HTML)
6. **帖子详情**:PostListVC(楼层 Section、页导航、进度保存/恢复)+ GalleryVC + 站内链接路由
7. **登录**:LoginVC + SessionStore(响应校验/formhash 刷新/掉线通知)+ Keychain
8. **收藏**:FavoritesVC(列表/移除)+ 详情页添加收藏
9. **历史**:HistoryVC(搜索/清空/删除)
10. **黑名单管理**:BlacklistVC / BlackWordVC
11. **我的 Tab + 设置**:MeVC / SettingsVC / AboutVC(开源许可)
12. **打磨**:空态/错误态统一件、深色模式走查、Dynamic Type 走查、模拟器全流程回归

### M2(预告)
回复/引用/发帖/编辑编辑器(KPSwitch 等价方案:iOS 输入 accessory + inputView 切换)、表情面板、图片上传双通道、私信、通知、搜索、个人空间、评分举报、WebView 兜底登录。

### M3(预告)
帖子备份(离线)、分享长图、小黑屋、投票签到(App 后端 sid)、typeid 筛选、页内搜索、只看他、多 host 容灾、深链。

## 6. 测试策略

- **单元测试**(target `S1GooseTests`):ResponseCleaner(JSON 怪癖样例)、BlockSplitter(真实 Discuz HTML 样本:引用/代码/表格/表情/附件)、黑名单过滤逻辑、ThreadLink 解析。
- **集成验证**:模拟器手工回归(§5 M1-12 的走查清单);登录/发帖等写操作用真实账号人工验证(仓库内不留测试账号凭据)。
- 数据库测试用 in-memory(`DatabaseQueue()` 临时库)。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| Discuz JSON 过脏,清洗后仍失败 | ResponseCleaner 分级修复 + 日志原文;必要处退化为展示原始错误 |
| 渲染长楼性能(40 楼 × 富文本) | 解析/归因后台线程;图片 cell 固定比例;复用 diffable 增量刷新 |
| 会话 cookie 失效静默 | 每响应校验 member_uid,统一掉线通知,需要登录的页展示引导 |
| 附件上传链路复杂(多通道) | M1 不做;M2 按 docs/forum_attachment_upload_flow.md(S1-Next)复刻 |
| 表情资源体积 | 只内置常用组,URL 映射缺失时降级线上图 |
| S1 服务器对非官方客户端限制 | UA 保持默认;多 host 容灾在设置中可覆盖(M3) |

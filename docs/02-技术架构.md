# S1 Goose 技术架构文档

> UIKit + SQLiteData 原生实现。本文描述分层、并发、网络、渲染管线、持久化与关键决策。

## 1. 总体分层

```
┌─────────────────────────────────────────────────┐
│ Presentation (UIKit)                            │
│  ViewControllers / Cells / Gallery / Menus      │
│  全部 @MainActor,零网络/DB 直接调用              │
├─────────────────────────────────────────────────┤
│ Application Services                            │
│  ForumRepository · ThreadRepository ·           │
│  PostRepository · FavoriteService ·             │
│  SessionStore · BlacklistService ·              │
│  HistoryService · ReadProgressService           │
│  async/await;组装「网络数据 + 本地过滤」          │
├──────────────────────┬──────────────────────────┤
│ Networking           │ Persistence              │
│  S1APIClient         │  SQLiteData(GRDB)        │
│  DiscuzMobileAPI     │  AppDatabase.swift       │
│  ResponseCleaner     │  @Table 模型 + 迁移       │
│  JSON 容错解码        │  Keychain(凭据)          │
│  HTTPCookieStorage   │  UserDefaults(设置)      │
└──────────────────────┴──────────────────────────┘
```

- **单向依赖**:VC → Service → (API | DB)。VC 不 import SQLiteData 之外的网络细节;Service 不持有 UIKit。
- **模型归一**:API 层产出 `Sendable` 值类型模型(Forum/Thread/Post/…),渲染前的**黑名单过滤在模型组装层**(对齐 S1-Next `Posts.filterPostList`),而非 UI 层。

## 3. 并发模型

- Swift 6 语言模式。UI 全 `@MainActor`;模型为 `Sendable` struct;Service 层无共享可变状态(或 actor 隔离)。
- VC 发起请求:`Task { … }` + 取消(页面 `viewWillDisappear`/重复请求时 cancel 旧 Task)。
- 渲染管线的 HTML 解析与 NSAttributedString 构造放**后台**(`Task.detached` 或 Service 层),仅 UIKit 使用回主线程。
- DB:`try await database.read/write { … }`;SQLiteData `@Fetch*` 属性包装器仅用于少量**常驻观察**(M1 基本用一次性 read,列表为网络数据源)。

## 4. 网络层设计

### 4.1 会话与 Cookie
- `URLSession.shared` 配置改用默认 `HTTPCookieStorage.shared`(自动持久化 Discuz `<前缀>_saltkey/_auth` cookie,重启后仍有效)。
- **User-Agent**:默认 URLSession UA 即可(对齐 S1-Next 用默认 UA 的做法)。
- `ApiVersionInterceptor` 等价物:请求构造器对论坛域名且缺 `version` 参数的 URL 统一补 `version=1`(forumdisplay 用 4、viewthread 可 4)。

### 4.2 S1APIClient
- 唯一入口 `func send(_ request: APIRequest) async throws -> Data`,职责:
  1. 组装 URL(base URL 可配置,默认 `https://stage1st.com/2b/`);
  2. `application/x-www-form-urlencoded` 表单体编码;
  3. 发送、读 HTTPCookie;
  4. **JSON 容错清洗**(`ResponseCleaner`,见 4.3)后交给 `JSONDecoder`(非严格:`.iso8601` 不适用——Discuz 全为字符串);
  5. 错误映射(`APIError`)。
- **formhash 管理**:每个响应的 `Variables` 混入 `member_uid / member_username / formhash`。`SessionStore.validate(variables:)` 在每次响应后更新登录态与 formhash;写操作前 formhash 为空则先请求 `module=toplist` 刷新(等价 `ensureAuthenticityToken`)。
- **掉线判定**:`member_uid` 为 "0"/空 → 视为未登录,发通知 `sessionDidLogout`,UI 返回未登录态。

### 4.3 ResponseCleaner(JSON 容错)
Discuz mobile API 返回非严格 JSON。清洗管线(纯函数,可单测):
1. `Data → String`(utf8,失败试 gbk 转换兜底→ M1 仅 utf8,遇错报错);
2. 修复空值:`:,` → `:null,`、`:,}` → `:null}`(S1-Next RawJsonConverterFactory 同款规则);
3. 修复未加引号的 key(可选兜底,正则 `([{,]\s*)([A-Za-z_][\w-]*)(\s*):` → `"$2":`),仅在首解析失败时启用;
4. `\uXXXX` 由 JSONDecoder 原生处理,无需额外步骤;不完整转义串做最长合法截断兜底。

### 4.4 错误体系
```
APIError
├── server(String)            # 顶层 "error" 字段
├── message(String, String)   # Message.messageval 非 *_succeed
├── needLogin
├── authenticityToken         # formhash 不可得
├── network(URLError)         # 离线/超时
└── decoding(Error, Data)     # 清洗后仍失败
```
- Service 层把 `APIError` 映射为用户可读文案(中文);VC 展示 banner/alert + 重试闭包。

## 5. 帖子渲染管线(核心)

### 5.1 流程
```
API JSON message(HTML 片段)
  → PostPreprocessor    # 1) 附件占位 [attach]aid[/attach] → <img>/<attach>
                        # 2) reply_wrap → blockquote;黑名单引用 → [已被抹布]
                        # 3) 颜色名→hex;smiley 识别;相对 URL 补全
  → SwiftSoup 解析 DOM
  → BlockSplitter       # 顶层遍历 → [PostBlock]
  → HtmlAttributedBuilder  # DOM 片段 → NSAttributedString(后台线程)
  → [PostBlock]         # Sendable,与 UIKit 解耦
  → UICollectionView DiffableDataSource(每楼层一个 Section)
```

### 5.2 块模型(RecordType)
```swift
enum PostBlock: Sendable {
  case text(AttributedStringModel)        // 段落,含内联表情附件
  case image(PostImage)                   // 独立图片(url, ratio, attachmentId?)
  case quote(quoteAuthor: String?, inner: AttributedStringModel)
  case code(String)
  case attachment(name: String, url: URL, sizeKB: Int?)
  case fallback(AttributedStringModel)    // 表格等降级
}
```
- 内联表情:URL 含 `image/smiley/` → 按 URL 尾段映射本地 Assets 表情(缺失则降级为线上小图附件)。
- 图片块只挑「独立成段、非表情」的 `<img>`;`src` 为占位(none.gif)时取 `file`/`zoomfile`。
- 附件 URL:`PostAttachment.url + attachment` 拼接;`forum.php?mod=attachment&aid=…` 下载链接保留。

### 5.3 HtmlAttributedBuilder 规则
- 不用 `NSAttributedString(html:)`(主线程 + WebKit 依赖),自建 DOM→归因映射:
  - 基准 `.body`;`<b>/<strong>` bold、`<i>/<em>` italic、`<u>` underline、`<s>` strikethrough;
  - `<font color>` 前景、`<font size="n">` 相对倍率(1–7 → 0.8/0.9/1.0/1.15/1.3/1.5/1.7);
  - `<a href>`:站内(thread/forum/uid 规则)→ `s1goose://` 内部路由;外部 → 保留原 URL;
  - `<br>` 换行、`<hr>` 分隔线、`<img>`(内联表情)→ NSTextAttachment(基线对齐);
  - `<div class="reply_wrap">` 由前置处理转 `blockquote`,嵌套引用展开为一层 + 「…引用」提示。
- 复杂结构(`<table>`)走 `fallback`:整体文本化 + 换行保序(M3 可做原生表格)。

### 5.4 单元结构
- Section = 楼层;`header` 头像/昵称/时间/楼层;`text/image/quote/code/attachment/fallback` 各自 Cell;自尺寸(`estimated` 高度)。
- 40 楼/页一次性入 diffable;翻页追加 Section;跳页 = 重建。
- 图片高度稳定性:图片 cell 占位高度优先级 = `ImageDimensionStore` 记录的真实像素比例 → HTML `width/height` → 退化估算;加载成功后把真实像素尺寸写入 store(内存 + Caches JSON,LRU 2000),再次滚动到同一张图时占位高度即与最终一致。`applySize` 仅在尺寸实际变化时才 `invalidateLayout`,`updateSize` 尺寸未变则跳过约束重建——避免每张图落地都触发整体重排、滚动条跳动。超高图统一以「可用宽 × 2.5」封顶,占位与落地一致。

## 6. 持久化设计(SQLiteData)

- 入口:`prepareDependencies { $0.defaultDatabase = try appDatabase() }` 等价物在 `AppDelegate` 完成(UIKit 无 SwiftUI Scene,直接构造 `DatabasePool` 并存 `AppDatabase` 单例)。
- 迁移:`DatabaseMigrator`,`eraseDatabaseOnSchemaChange` 仅 DEBUG。
- 表:`blackList / blackWord / history / readProgress`(详见 `04-数据模型.md`)。
- 黑名单内存快照:`BlacklistService` 维护 `Set<Int>` + `Set<String>`(id/用户名),写操作后重建;过滤纯内存,无每楼 DB 查询。
- 凭据:Keychain(kSecClassGenericPassword,service=`com.bitxeno.s1goose.account`,单条 JSON);iOS 端不落数据库。

## 7. 状态与错误呈现(统一件)

- `StatefulContainerView`:loading(全页)/ error(icon+文案+重试)/ empty(icon+文案)。
- 列表追加失败:footer 显示「加载失败 · 点按重试」,不清空已有数据。
- 全局 toast(轻提示)用 `UILabel` + 动画(M1 仅用于「已复制」「已收藏」)。

## 8. 日志与调试

- `os.Logger`(subsystem `com.bitxeno.s1goose`,category: net / db / render)。
- DEBUG 构建开启 GRDB SQL trace(对齐 SQLiteData 指南);ResponseCleaner 失败时输出前 2KB 原文辅助排查。
